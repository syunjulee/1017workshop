## 交付範圍

| 模組 | 修正後的行為 |
|---|---|
| 自己／AI／定案 | 自己三張卡與理由獨立呈現；AI 引句有虛構原文；逐項採用或不同意並留理由；本人整理四項已定義欄位，模擬團隊核對後再次本人確認；保存定案快照 |
| 三面鏡 | 本人先鎖定；拒絕須理由；同項不重複計數；AI 不足可用兩面鏡，光環留白，不計三方對齊 |
| Skill A | 管理者手動放入虛構職缺，逐字核對引句後啟用；職涯卡才引用，沒有薪資則明示無資料 |
| Skill B | 設計依據，非平台背景研究蒐集器；不執行真實研究或人口資料蒐集 |
| Skill C | P2 需名片定案與模擬關卡 2 開放；三題定位；五章可選；作答進審核佇列，核對通過並揭曉才成長；同關不累加；三題安排回憶，錯誤不扣分 |
| Skill D | 每題可略過；把握、精力、時間與卡點依固定程式規則調整下一步，不呼叫 AI，不預填狀態或把同一天當三天 |
| B 面 | 先猜、載入兩份模擬訪談、同意說明、模擬審核，才能揭曉 |
| TA 迴圈 | 載入虛擬角色起點 → 實際操作 → 記錄有證據的回饋 → 建立問題與修改方案 → 實際改碼發布新版本 → 原任務重測 → 核對改善 |

## 操作方式

1. 進首頁，打開上方「團隊工作台」。
2. 在「TA 試跑與回饋」選一位角色。這只載入起點，不會生成通過結果。
3. 按任務實際操作；審核需要到工作台明確選「模擬核對」。
4. 回工作台記錄結果、畫面與步驟、模擬理解。未完成任務不能標完成；沒有操作不能保存測試結果。
5. 從回饋建立修改項目，填具體修改方案。填方案不代表程式已修改。
6. 修改程式並更新 TeamTownCore.BUILD、index.html 的進度 KEY、資產版本參數與文件版本，再發布。
7. 保留本機回饋，回原問題按「下輪用原任務重測」，完成後記錄回饋。相同版本不能結案；重測未完成也不能結案。
8. 在「存檔／Harness」下載執行紀錄、TA 回饋及問題紀錄。學員進度為分頁暫存，可單獨匯出／匯入；TA 紀錄在本機，不會分享給組員。

## 判讀方式

- 易用性：任務獨立完成／需協助／未完成／不可測，加上畫面與步驟證據。
- 操作次數：輔助觀察，不能當成耗時或真人效能基準。
- 虛擬角色的理解、價值：設計假設，不能當成真人訪談或滿意度。
- 「這像我嗎」、AI 學習與回饋幫助程度 0–10：保留給真人；原型不代填分數。
- 本輪沒有 A/B、統計顯著性或自動產生成功率。

## 限制與待定

這是前端功能原型：沒有登入／正式管理權限／後端隱私過濾、跨裝置同步、真人訪談、真 AI、外部搜尋與正式資料庫。工作台是模擬操作，不是存取控制。請勿輸入真實或敏感資料。

PRD 的十題名片定案僅四項已有定義，本版只收這四項，不擅自補造六題。B 面與嚮導的內容仍是既有虛構示例和人工核對，不宣稱模型品質已驗證。Skill A 的職缺能力是人工示例整理，不宣稱 AI 自動分析。虛擬 TA 不能代替真人滿意度。實際改碼與發布需要團隊操作，不是按下重測就自動修復。
